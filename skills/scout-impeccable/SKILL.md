# Research Scout refinement with Impeccable

Use the reviewed Impeccable principles to make an existing research workspace clearer. This is a project adapter with a licensed reference subset, not the complete upstream runtime. Provenance and update instructions are in [UPSTREAM.md](UPSTREAM.md); imported file hashes are in [UPSTREAM.json](UPSTREAM.json).

## Start from the current brief

The user's latest request and authorization, applicable AGENTS.md instructions, current implementation and rendered evidence establish the working contract. Preserve existing project conventions when no formal design-system document exists. Missing DESIGN.md does not make the application a blank canvas.

Classify the target by its task: search controls and result selection are **Operate** surfaces; source prose and README reading are **Read** surfaces. Read [Operate and Read guidance](references/upstream/operate.md). Precision, familiar affordances and useful information density can be the distinctive design decision.

For the current Research Scout baseline, retain the light navigation shell, question composer, project/query actions, settings and information icons, compact timing, visible saved AI focus, four resource tabs and right reader unless the user explicitly changes that scope. Preserve source identity, notes, explicit media actions and honest access, relevance and loading states. Separate saved-search facts from next-search preferences. Mockup approval alone does not authorize application adoption, provider/model work or changes to live research.

## Load the guidance the target needs

- **Scoped polish:** [polish](references/upstream/polish.md). Distinguish a missing token, inconsistent implementation, conceptual mismatch and local defect. Fix blocked tasks and misleading states before cosmetic drift.
- **Grouping and density:** [layout](references/upstream/layout.md). Name the primary task path and spatial thesis; use proximity and alignment before adding boxes.
- **Reading and hierarchy:** [typeset](references/upstream/typeset.md). Keep UI roles stable; justify any separate prose face by its reading purpose. Use real source titles and descriptions to tune measure and wrapping.
- **Labels and state explanations:** [clarify](references/upstream/clarify.md). Preserve factual meaning and recovery paths. A concise message must still distinguish empty, filtered, failed, blocked and pending work.
- **Audit or critique requests:** read [the engine boundary](references/engine-boundary.md) first. The imported [audit](references/upstream/audit.md) and [critique](references/upstream/critique.md) documents explain upstream methods; their embedded shell commands are reference material, not steps this guidance-only bundle can execute.

Treat broad aesthetic prescriptions in upstream references as design inputs. They do not overrule a confirmed sidebar, palette, content requirement, accessibility behavior, user preference or approved workflow. Do not replace the product's identity under the name of polish.

## Compare or implement within the authorized scope

For comparisons, keep authored content, counts and interactions identical. Differentiate the reading hierarchy, result-row construction, reader emphasis or density so choices remain recognizable beyond a palette swap. Record what each option improves and what it costs. Keep prototype files separate from application source.

For an approved application change, work at the narrowest level that owns the inconsistency. Promote tokens or components only when repeated intent warrants reuse. Preserve revision, selection, draft and request ownership while changing presentation.

Review representative desktop, intermediate and phone layouts with the actual interaction path: keyboard focus, disclosure and recovery, reader scrolling, long/missing text, source expansion, progressive results and reduced motion. Record the source/render evidence and meaningful checks performed. A screenshot of an authored preview establishes a visual result, not a live retrieval-quality measurement.

Report guidance-only work as **Impeccable-guided design review**. State when the upstream engine, detector, overlays and native audit workflows did not run; never invent their findings or scores.
