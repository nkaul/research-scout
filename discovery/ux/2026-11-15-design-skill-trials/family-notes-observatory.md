# DataPulse Observatory — direction 08

November 15, 2026. Exactly one additional, standalone prototype, created after approval of a more direct reimagining of the supplied reference. The seven earlier directions remain separate and unchanged. This prototype does not adopt a new Research Scout application design.

## Design source and authority

Primary reference: [DataPulse SaaS analytics landing page](https://www.uupm.cc/demo/saas-analytics-dashboard#features). Its hero, features and full page were rendered and visually inspected. The reference is a marketing page containing an analytics preview; its product interactions were not verified.

The Observatory borrows the reference's composition: inset floating navigation, an oversized two-column introduction, a layered preview illustration, a generous uniform three-by-two feature grid, and an embedded product workbench further down the page. It also adapts navy type, cool pale surfaces, delicate blue borders, restrained depth, colored line icons and blue-to-violet display emphasis. It does not copy reference images, font binaries, promotional claims, analytics data, pricing, source code or product content.

The project `scout-impeccable` and `scout-ui-ux-pro-max` skills informed hierarchy, interaction grouping, responsive behavior and reading measure. Their normal recommendation to preserve the current sidebar topology is explicitly superseded here by the approved request for a fundamentally different reference-led composition. The upstream native audit/detector was not run. The supporting reference analysis records local catalog guidance in `reference-reimagined-brief.md`; this design is not claimed to be an automatically generated upstream recommendation.

## Spatial thesis

The primary path is **question → research map → original evidence**. The introduction makes the research question the starting point; the illustration shows how resource types relate to that question. Six equal cards make the four evidence paths, query context and source-linked observations discoverable. The evidence desk then becomes a quieter Operate/Read surface, with local resource tabs, a tiled evidence collection and an unrotated reader.

The decorative session preview is tilted; the actual controls and workbench are level. There is no left sidebar, imported workspace shell, stacked-list template or shared preview renderer. The larger introductory typography and section rhythm are intentional in this direction, contrasting with the seven more operational workspace trials.

## Functional translation

| Reference element | Observatory adaptation |
| --- | --- |
| Floating product navigation | Research map, evidence desk, prototype explanation and design-gallery links; an operable phone menu. |
| Hero headline and call to action | Editable original question, Material-blue Explore question button, Sources/Date/Limits/AI controls and authored query context. |
| Layered analytics illustration | A self-authored SVG evidence orbit and an actual authored source excerpt. No fabricated revenue, security, confidence or performance figures. |
| Six feature cards | Papers, Videos, Data, Repos, query focus and source-linked Notes. Each card leads to a corresponding local action. |
| Embedded dashboard preview | A functional local evidence workbench with resource tabs, filtering, source reader, metadata, expansion and Notes. |
| Dashboard status | Explicit local replay progress and measured browser replay duration; illustrative credit usage is labeled and no credits are spent. |

Initial authored examples remain 3 papers, 2 videos, 2 datasets and 2 repositories, using the same general question and source wording as the original comparison fixtures. Data was copied by value; `shared/mockup.js` and `shared/base.css` are not imported or executed.

Settings prepare the next local replay. Publication dates filter paper/video years; dataset versions and repository activity keep their own meaning. Source choices affect the corresponding paper/video example pool. Limits are finite, zero disables a view, and replay never fills an unavailable pool with invented records. A changed question is displayed as the user's draft; the interface explicitly explains that the example focus and records remain authored rather than newly inferred or retrieved.

Resource selection is explicit. The reader offers Overview, Metadata and Notes, source-attributed Key points/Original text, inline expansion and a local document/video storyboard. Source notes retain drafts across view changes and can be saved under a prototype-specific browser-storage key. No backend persistence or real media acquisition is implied.

## Typography, assets and responsive behavior

- Display: local Avenir Next / Trebuchet MS / Segoe UI fallbacks, with a deliberate large hero role and a smaller stable workbench hierarchy.
- Reading: local Open Sans / Segoe UI / Arial fallbacks. No font or asset downloads.
- Palette: Material blue for primary controls; blue/violet display emphasis; green only for meaningful example-ready and source-availability states.
- Assets: self-authored inline SVG symbols and an evidence-orbit illustration. No external icon package, chart library or image dependency.
- Layout: centered page and floating navigation on desktop; a split introduction and three-column feature grid reflow into a single-column introduction and two-/one-column cards. The reader remains operable inline on narrow screens.
- Interaction: visible focus, native inputs, tablist keyboard movement, Escape/focus restoration for settings and navigation, a cancelable progressive local replay and reduced-motion support.
