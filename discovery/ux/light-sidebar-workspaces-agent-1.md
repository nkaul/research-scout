# Light sidebar workspaces — UX research agent 1

**Checked October 29, 2026.** Research set: knowledge, reading, research and productivity workspaces. This responds to the user's preference for the light, restrained feel of `starter.cal.com`, with the richer navigation, settings and working controls associated with Linear. Framework restrictions no longer apply.

All **15 counted references below have a publisher-provided light UI asset that was visually inspected**. These are public product images, help illustrations or animation frames; no authenticated application was exercised. A currently available help page can retain an older screenshot, so its presence is not proof of the latest deployed interface. Dates and platform limitations are recorded below. Design recommendations are judgments for Research Scout, not measured usability results.

## Open these five first

1. **Capacities** — strongest overall composition: a quiet light sidebar, restrained pastel object icons, clear pinned/type groups and a separate white reading surface with an outline/metadata pane.
2. **Fibery** — strongest richer-control reference: light nested navigation and a compact, consistent view toolbar. Study how substantial configuration fits around the main work.
3. **Condens** — closest research-workspace organization: global destinations, a visibly scoped active project, and a separate evidence/report area.
4. **Slite** — strongest recent simplification: document navigation remains visible while agent sources, usage and configuration move into settings.
5. **Elicit Library** — closest paper-list reference: collection counts, useful bibliographic rows, content-availability labels and selection-dependent actions.

## Detailed observations and controls

### 1. Capacities

[User interface guide](https://docs.capacities.io/reference/user-interface) and [research tour](https://capacities.io/research). The light overview clearly separates the navigation, white editor and outline/metadata inspector. Small pastel icon tiles give object types identity without coloring the entire workspace. Pinned objects sit apart from the type catalog; account/settings/appearance controls sit in the footer. The guide documents focus mode and rearrangeable type/pin groups.

Apply to Scout: **(1)** distinguish durable destinations from pinned research runs/shortlists; **(2)** put source outline, provenance and check details in an optional inspector. Borrow the grouping and surface hierarchy; the exact screenshot text contrast was not measured. Settings behavior was read, not exercised.

### 2. Fibery

[2025 interface study, published January 21, 2026](https://fibery.com/blog/startup-diary/fibery-2025/) and [Atomic Research template](https://fibery.com/templates/atomic-research). The inspected light screen has a subtle gray sidebar, personal shortcuts, expandable spaces and a pale blue selected row. Search, fields, filter, sort, color and New share a single toolbar rhythm. The template describes linked experiments, facts, insights and recommendations; its workspace was not interacted with.

Apply to Scout: **(1)** place list display controls in a compact toolbar, separate from Search submission; **(2)** reserve nested navigation for project/run context while keeping source identity visible in the main pane. Adopt the organization without adding a customizable database builder to Increment 1.

### 3. Condens

[Getting started](https://condens.io/help/-/getting-started/), [split-screen guide](https://condens.io/help/using-condens/tips-and-shortcuts/split-screen-mode/) and [project information fields](https://condens.io/help/using-condens/research-repository-functionality/project-information/). The light project image shows global navigation above a boxed Active Project group; settings and collapse sit at the bottom. The separately inspected [analysis image](https://public-files.condens.io/images/features/qda/sidebar.png) demonstrates evidence alongside a report. The guide documents resizable panels and reusable project metadata.

Apply to Scout: **(1)** show the active question/run scope as a contained navigation group; **(2)** allow an available source to remain open while the user edits a human inclusion reason. The qualitative-analysis features are reference material, not new product commitments.

### 4. Slite

[September 2026 sidebar/change article](https://slite.com/changelog/slite-mcp-is-now-in-the-claude-directory) and [workspace settings](https://slite.com/help/udZ9hefNXMiDcv/Workspace-Settings). The inspected light composite shows Search, Agent triage, favourites and Docs in the main navigation. A separate settings navigation groups agent configuration, sources and AI usage. Small outlined icons and modest selected backgrounds keep the interface quiet despite substantial configuration.

Apply to Scout: **(1)** keep Research and Saved Shortlist prominent while provider connection/configuration lives in Settings; **(2)** use scoped attention badges for actionable failures or review work, with full operation detail available separately. The image is a changelog composite; no responsiveness, keyboard behavior or permission settings were tested.

### 5. Elicit Library

[Library product tour](https://elicit.com/solutions/library) and [systematic-review setup guide](https://support.elicit.com/en/articles/14759154-systematic-reviews-in-elicit). Its light collection image shows counts, a clear selected row, search, sort/filter and structured source metadata. A second inspected [table image](https://framerusercontent.com/images/ZrH7MuNx3Ccu4P3sAW5N1ig9UzM.png?height=2880&width=2880) shows content availability and selection-dependent actions. The guide documents a separate setup surface for workflow settings.

Apply to Scout: **(1)** use readable source rows with content-state labels and collection counts; **(2)** reveal shortlist/export actions when relevant while keeping the current run scope legible. Elicit's automated workflows or deduplication/merge semantics are not adopted; Scout must retain its own provider observations and human authority.

### 6. Heptabase

[Interface logic guide](https://wiki.heptabase.com/user-interface-logic) and [product tour](https://heptabase.com/). The inspected light navigation has labelled destinations and a clear Research a topic action. The separate light product image demonstrates a source/board, PDF and contextual discussion side by side. The guide documents pinned tabs, tab folders/groups, contextual tools and display controls. These are desktop-style product references; no app was opened.

Apply to Scout: **(1)** keep the source visible while related notes/check observations open beside it; **(2)** give saved research contexts stable labelled navigation instead of accumulating anonymous panels. The bright app icons are an optional identity direction; introducing whiteboards or full-PDF analysis would be a separate scope decision.

### 7. Craft

[Calendar and customization guide](https://support.craft.do/en/plan-and-do/calendar) and [styling guide](https://support.craft.do/hc/en-us/articles/10293992410780-Document-Styling). The inspected animation frames show a soft lavender/near-white native sidebar, a visible space switcher, a separate folder group and restrained selected rows. Calendar has explicit Daily Notes, Tasks and Events controls; the guide documents customization of visible content. These are macOS screenshots, not proof of identical Windows/web layouts.

Apply to Scout: **(1)** try a subtle tinted navigation surface beside white source content; **(2)** make display density/content choices explicit and local to the view. Keep provider/search scope controls separate from cosmetic view controls. Animation opening frames were inspected, not a complete interaction recording.

### 8. Readwise Reader

[Default filtered views](https://docs.readwise.io/reader/guides/filtering/default-views), [navigation](https://docs.readwise.io/reader/docs/faqs/navigation) and [appearance](https://docs.readwise.io/reader/docs/faqs/appearance). The verified light sidebar has Library with typed subcategories, Tags and Feed; the preferences image shows a categorized left settings column and separately configurable side-panel visibility. The current guide explicitly documents light/dark/auto appearance and customizable pinned views.

Apply to Scout: **(1)** distinguish source type from review state, such as available versus shortlisted; **(2)** let the source inspector close without leaving the results, with a persistent user display preference. The public marketing hero is dark and is deliberately excluded as the viewing link.

### 9. Notion

[Sidebar guide](https://www.notion.com/help/navigate-with-the-sidebar) and [preferences/light appearance](https://www.notion.com/help/account-settings). The inspected light image demonstrates subtle gray navigation, section headings, selected rows and a compact Sort/Show/Move menu. It is an earlier sidebar image still embedded in current help; the live documentation now describes sidebar tabs and settings in the workspace switcher, so do not copy its old locations as current behavior.

Apply to Scout: **(1)** separate recent/pinned work from the full saved-run collection; **(2)** limit initially displayed items with a clear More affordance. Use the current guide for behavior and the dated screenshot for surface/spacing inspiration.

### 10. Coda

[2025 UI refresh](https://help.coda.io/hc/en-us/articles/39555750800397-Coda-s-2025-UI-refresh). The inspected light workspace home has workspace/folder navigation, selected destination, compact list rows and restrained contextual actions. The second image shows consolidated document actions with Doc settings in one menu. The article explains the distinction between account administration, workspace options and document controls. This is explicitly a 2025 example, not a claim about every current Superhuman/Coda screen.

Apply to Scout: **(1)** make application settings, run actions and per-source actions distinct; **(2)** use consistent menu entry points and group import/export/history with the artifact they affect. Avoid duplicate settings buttons that require memorizing which menu holds an option.

### 11. Raindrop.io

[Product tour](https://raindrop.io/) and [official help](https://help.raindrop.io/). The inspected light image shows nested collections, recognizable collection icons, an active row, item counts, a query field, sort and tag filters above a readable resource list. The product page separately offers multiple view styles and light/dark appearance. Settings screens were not visually reviewed.

Apply to Scout: **(1)** keep collections/shortlists in the left navigation while filters remain close to the results they affect; **(2)** use small provider/resource marks plus concise metadata to improve scanning. Collection emoji are useful inspiration, but provider identity must remain labelled and must not imply blended provider searches.

### 12. Tana Outliner

[Outliner sidebar guide](https://outliner.tana.inc/learn/features/sidebar) and [November 2025 update](https://outliner.tana.inc/blog/tana-current-monthly-update-november-2025). The inspected light help image contains a November 2025 date and shows Today, Supertags, AI chat, create/search, pinned objects and expandable workspaces. The update documents a resizable/collapsible sidebar, configurable visible items and light-mode contrast refinements. **This entry is Tana Outliner**, not the different current general Tana interface described at `tana.inc/learn/features/interface`.

Apply to Scout: **(1)** keep pinned questions/saved work above the larger navigation tree; **(2)** offer an intentional focus/collapse option while preserving a clear way back. No live resize or saved preference was tested.

### 13. NotePlan

[Current product tour](https://noteplan.co/) and [theme preferences](https://help.noteplan.co/article/20-how-to-change-the-theme-colors-fonts-etc). The full inspected hero is a **web workspace screenshot** showing `app.noteplan.co`, with light settings/search/create, team/private groups, folders and tags, and a right calendar. Its sample content is March 2024; the current tour also supplies an inspected July 2026 reading/calendar detail. NotePlan also has native apps; the older full hero does not prove today's native or web build.

Apply to Scout: **(1)** use visible groups to separate research contexts from labels/facets; **(2)** maintain a stable reading column with useful optional context beside it. Calendar/time-blocking features are not relevant requirements for Scout.

### 14. Todoist

[Product features](https://www.todoist.com/features) and [sidebar configuration](https://www.todoist.com/help/todoist/features/customize-the-sidebar-and-navigation-menu-in-todoist-S9JLTYqZV). The inspected desktop project scene has a warm off-white navigation panel, grouped favourites, small colored project marks and a pale green selected state. It is a **stylized publisher illustration** with abstracted labels, not a full raw app screenshot. The current help documents showing/hiding destinations and task counts.

Apply to Scout: **(1)** give the active shortlist/run a quiet tinted selection instead of a saturated bar; **(2)** show counts selectively, without placing a badge on every navigation item. Its minimalism is useful as a lower-density comparison alongside Fibery and Condens.

### 15. Nuclino

[List view](https://help.nuclino.com/ccaed59c-use-the-list-view), [table view](https://help.nuclino.com/ae3bcd53-use-the-table-view) and [workspace settings](https://help.nuclino.com/16fe1695-access-the-workspace-settings). Both inspected images are light. The list view has a quiet collection tree and pinned pages beside a white document; the table provides clear fields, muted status pills and view tabs. Settings are scoped to the workspace, including default view, fields and export. Example content is older and is not release evidence.

Apply to Scout: **(1)** keep the source index and reading surface visually connected; **(2)** use field/column configuration in secondary controls while preserving readable default metadata. This is a useful simpler baseline rather than the strongest visual identity reference.

## Implications for the next Scout design discussion

- Compare **Capacities + Fibery + Condens** for the main shell: light navigation, bounded research context, denser view controls and a reading/inspection pane.
- Compare **Slite + Coda** for settings: keep provider configuration, appearance and usage discoverable without filling the source-reading path with administration.
- Compare **Elicit + Reader + Raindrop** for source triage: structured rows, content state, small metadata and explicit saved collections.
- Use one controlled accent for selection and primary action; use small consistent icons with text labels. Pastel surfaces and gray metadata still require contrast verification in Scout's actual tokens.
- Preserve existing Scout behavior: progressive source rows, stable order/focus, explicit provider scope, human decisions and separate registry observations. These inspirations do not authorize hidden provider mixing, automated field reconciliation or additional product modules.

## Screened out of the counted light list

**Dovetail**, **Anytype**, **Superlist** and **Asana** were researched. Dovetail's March 2026 sidebar image, Anytype's February 2026 tabs image and Superlist's current main product image were actually dark. Asana's official overview combined white work panes with a charcoal sidebar. Those assets were not counted as light matches. A documented light-theme option alone is insufficient evidence of the visual composition the user asked to see.

No application code, prototypes, credentials, accounts, subscriptions or product data were changed. Assets were read into temporary files for visual inspection; only this research report is added to the repository.
