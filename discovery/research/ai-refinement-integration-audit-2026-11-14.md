# Shared AI refinement — integration audit

November 14, 2026. Analysis agent audit of the implemented Search/Exploration, Data, Repos and answer-generation paths. Initial findings below describe the code **before this shared-plan change**; the closing review record distinguishes subsequent implementation. No live model/provider requests, credential changes or allowance increases were made for this audit. Official documentation browsing was limited to context and structured-output guidance.

## Existing behavior and concrete gaps

| Path | Already implemented | Gap found |
| --- | --- | --- |
| Topic planning | [retrieval.py](../../backend/src/research_scout/retrieval.py) executes a real structured model planning call, then provider-specific retrieval, independent relevance review and at most one repair round through LangGraph. SearchPlan includes intent, domain, object/intervention/outcome/boundary, keywords, tags, facets, inferred assumptions and clarification. | The prompt and provider-query schema cover scholarly/video discovery only. Dataset/repository query intent is not separately planned. Structured missing-information and expansion provenance are absent. |
| Saved canonical query | SearchPlan has resource-neutral lexical/semantic queries and separate provider-specific expressions. | `_interpret` overwrites the saved root query pair with the first literature provider's expressions. These can contain provider-specific syntax or narrower corpus choices, although the UI presents them as the general retrieval query. |
| Data and Repos | [datasets.py](../../backend/src/research_scout/datasets.py) `problem_context`, imported by [repos.py](../../backend/src/research_scout/repos.py), requires a saved agentic discovery plan, freezes context/fingerprint and preserves literature filters separately. Explicit lookup starts isolated specialists; opening tabs performs saved reads only. | Both consume that overwritten root lexical query. Their adapters can safely quote/filter syntax, but cannot recover a lost resource-neutral query or manufacture model-planned dataset/repository intent. |
| Follow-up context | Planner includes the latest two prior user messages. | It omits the prior interpreted intent/frame and the assistant's clarification question. An answer such as “the former” can therefore lose the disambiguation choice; a follow-up may drift from the earlier research object. |
| Answer generation | [conversations.py](../../backend/src/research_scout/conversations.py) binds saved evidence from the preceding resource turn, admits live records and preserves explicit streaming/citation/budget gates. [generation.py](../../backend/src/research_scout/generation.py) uses one bounded evidence-only model call with no retrieval tools. | The prompt contains the current raw answer question and source excerpts, without the originating saved intent/frame, assumptions or unknowns. Data/Repos snapshots are separate stores and are **not** generation evidence in this implementation. |
| Transparency | [retrieval-focus.tsx](../../frontend/src/components/retrieval-focus.tsx) distinguishes saved model input, planned provider queries and actual provider arguments; [search-refinement.tsx](../../frontend/src/components/search-refinement.tsx) shows intent/frame, assumptions, keywords/tags, query history and relevance outcomes. | There is no four-lane plan, explicit missing-information/augmentation display or shared-plan provenance status. Older root query labels cannot establish that the saved expression was resource-neutral. |

The existing required-AI behavior is real: interactive topic searches submit the agentic path and block visibly on unavailable model configuration/allowance. Exact DOI lookup, saved reads, notes and access enrichment remain distinct actions. Low-level explicit deterministic diagnostics are not the interactive topic-search workflow. See [required retrieval and timing](../../system-design/required-agentic-rag-and-timing-2026-11-14.md).

## Bounded implementation recommendation

1. **One model-backed shared plan per new topic.** Extend the existing initial planning response with small explicit queries for Papers, Videos, Data and Repos. Preserve the canonical lexical/semantic pair; keep provider-specific expressions, repairs and executed arguments separate. Do not add a paid rewrite call when opening a tab or starting a catalog lookup.
2. **Model interpretation versus factual knowledge.** Record the clarified research question, domain/terminology basis, inferred expansions, assumptions and missing information. Technical synonyms can improve recall; missing population, dates, license requirements, dataset variables or code capabilities remain unknown unless supplied. Labeled assumptions are not established source facts.
3. **Essential uncertainty halts dispatch.** If a required distinction changes the intended domain/object, ask one concise clarification and admit no provider work. Permit an explicitly unready query state rather than forcing invented actionable expressions to satisfy schema requirements. Nonessential omissions can remain visible limitations without blocking a useful first search.
4. **Preserve follow-up scope.** Supply a bounded previous-turn structure containing its original question, saved intent/frame and clarification question. Treat it as untrusted context, not policy or verified evidence. The current user correction takes precedence over inferred earlier assumptions. Do not send full source corpora or every historical model body.
5. **Apply the matching lane query.** DataCite/Hugging Face and GitHub should receive their lane's query and selected terms. Keep catalog query terms distinct from global applicability keywords. Provider adapters retain ownership of safe syntax, supported filters, request budgets and exact executed-argument receipts. Literature publication windows must not become dataset/repository date requirements.
6. **Version and bind context.** Save the shared plan policy/version and fingerprint. New Data/Repos acquisition must not silently call a legacy paper-provider expression canonical. Historical records stay readable and accepted idempotent retries return the original receipt before consulting newer plan rules. If new acquisition requires a current plan, return an actionable re-run message; no hidden migration/model call.
7. **Frame generation without widening evidence.** Pass the originating evidence turn's saved shared question/intent/frame, assumptions and unknowns into the existing generation call as non-citable background. Count that structure toward the existing context-byte envelope. Bind it at admission so later conversation changes cannot substitute another plan. Keep the source/citation fence and current generation source types unchanged.
8. **Show planned versus executed work.** Display the canonical reformulation, all lane queries, extracted terms, inferred assumptions and unresolved questions. Provider traces remain the authority for actual dispatch. A model-planned lane does not imply the user started it, that a semantic endpoint exists, or that it produced usable results. Historic missing fields remain visibly unavailable.

## Budget and framework constraints

Retain LangGraph orchestration, provider-bound DeepAgents/application MCP specialists, isolated provider services and existing paid-call accounting. The current planning/review topology and shared **$0.25** ceiling are local implementation constraints; this task does not authorize a model/price change, new credentials, ledger reset or extra paid stage. Larger structured output must still fit the existing output-token and input-byte envelopes; a refusal, truncation or invalid plan fails visibly rather than triggering raw fallback.

OpenAI's structured-output guidance explains that schema conformance does not establish factual accuracy and recommends an explicit outcome for input that does not fit the task. Research Scout therefore still needs its own clarification, routing and provenance checks. [Official structured-output guidance](https://developers.openai.com/api/docs/guides/structured-outputs).

Conversation context must be deliberately supplied or managed; a new independent request does not reconstruct omitted prior turns. The proposed small saved-context structure is an application design choice, not a claim of automatic provider memory. [Official conversation-state guidance](https://developers.openai.com/api/docs/guides/conversation-state).

## Acceptance checks

- A model-authored canonical query survives a different OpenAlex/Crossref expression and later provider repair.
- Four lane queries share intent but remain resource-appropriate; Data/Repos receive their own terms and do not start another model call.
- A vague context/generation question either preserves a supported ML interpretation with labeled assumptions or asks clarification; no invented biomedical/date/population facts are inserted.
- Essential missing information blocks every affected acquisition; a clarification reply receives the actual prior clarification prompt and intent.
- A legacy plan remains readable; new acquisition follows the explicit compatibility rule; an already accepted request replays without model/provider work.
- Generation receives the exact originating context within its byte cap, retains source labels and does not treat assumptions as evidence or import Data/Repos records implicitly.
- UI shows model input, inferred expansions, unknowns, lane plans and real provider execution separately. Opening trace/tabs is GET-only and does not alter the shared allowance.
- Synthetic/scripted model tests prove contracts, not live relevance quality. Full regression, actual fixture MCP/browser validation and any live calls require separate truthful receipts.

## Implementation review record

Backend read-only review completed against the new [planning.py](../../backend/src/research_scout/planning.py), retrieval, Data/Repos and generation code. The adopted `scout-agentic-retrieval-v7` contract adds four model-authored resource query plans and context expansion in the existing initial planning call. Canonical queries are preserved; provider execution/repair has separate state. Actionable lane plans require nonempty extracted terms, while clarification can leave all lane plans null. The shared fingerprint excludes provider progress/repairs and includes the canonical interpretation and resource plans.

New Data/Repos acquisition requires that validated shared plan; historical results and previously accepted idempotent requests remain readable/replayable without new model work. Prior context includes the last two saved interpretations and actual clarification question. Generation's non-citable background is bound to matching provider/run/source/version observations from its originating turn and included in the existing byte envelope. Its source types and explicit paid-call topology are unchanged. No remaining blocking backend issue was identified in the agreed scope; the new scripted-model regressions cover canonical-query stability, clarification, lane admission, replay and exact generation source binding.

Frontend read-only review covers the shared AI-plan component, four resource lane queries/keywords, inferred-domain and missing-information labels, the main Search clarification prompt and continuation route, and the Data/Repos admission guard. The guard now requires usable current-plan fields and leaves fingerprint verification to the backend. Opening a trace or saved resource tab performs no acquisition. The final source-label correction is verified: a historical resource snapshot lacking its own lane query cannot silently fall back to the current plan while being labeled “Saved.” No remaining blocking finding was identified in the agreed frontend/backend scope.

Final full-suite/build/browser/actual-fixture validation remains the parent task's responsibility. This audit does not establish deployed live model relevance quality or claim an allowance reset. Initial findings above remain the pre-change baseline. Dataset/README synthesis, new providers, additional paid rewrite/review stages and a higher model allowance are outside this change.
