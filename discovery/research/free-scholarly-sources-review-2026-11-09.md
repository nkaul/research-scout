# Free scholarly sources and richer abstract coverage

**November 9, 2026 · research review and bounded live API probes; new providers proposed, not integrated**

**Later November 9 execution:** the user approved these additions; [implementation and live application proof](../../system-design/provider-expansion-2026-11-09.md) now supersede the proposed-only state below. This research review retains its original evaluation/probe scope and recommendations.

We can obtain richer records directly from scholarly APIs without any OpenAI requests. OpenAI is an optional answer writer in Scout, not its paper index or abstract source. The relevant constraints are source coverage, endpoint selection, abstract preservation/display, provider quotas and content availability.

## Basis in our existing research

This review revisited the [resource guide](project-research-resource-guide.md), particularly its scholarly directory and access/provenance category, and the [development handoff](research-scout-development-handoff.md), particularly sections 3.2, 4, 5.1–5.2, 7.3–7.4, 9.2 and increments 2–3. The handoff already recommends arXiv/PubMed domain branches, complementary scholarly coverage, explicit abstracts/snippets, and Unpaywall for access-location resolution. OpenAIRE, DOAJ, Europe PMC and CORE are already in the directory. The provider recommendations below refine that research against current primary documentation rather than replacing it with another generic catalog.

## Findings that change the integration priority

1. **arXiv is the strongest immediate addition for Scout's current AI/computing questions.** Its API returns author-supplied abstracts and versioned preprint IDs directly. It is narrower than a general scholarly graph; journal publication/review status and preprint versions need distinct records. [API manual](https://info.arxiv.org/help/api/user-manual.html), [API terms/rate policy](https://info.arxiv.org/help/api/tou.html).
2. **OpenAIRE is the closest reviewed free broad graph alternative.** It covers research products plus projects, organizations, sources and people. Current Graph API **V3** supersedes V1/V2. Keyword search and relationship filters do not establish native vector search. A two-record probe returned metadata without description text, so abstract uplift remains unproved. [Current API](https://graph.openaire.eu/docs/apis/graph-api/overview/), [research products](https://graph.openaire.eu/docs/apis/graph-api/research-products/).
3. **Europe PMC is particularly useful for biomedical/life-science questions.** Its REST `resultType=core` includes available abstracts, subject terms and full-text links. PubMed/PMC is a complementary domain route, with substantial overlapping records; do not count duplicate PMID/DOI records as independent evidence. [Europe PMC API](https://dev.europepmc.org/RestfulWebService), [NCBI API guidance](https://support.nlm.nih.gov/kbArticle/?pn=KA-05510).
4. **Unpaywall is not an independent replacement for OpenAlex.** Its current documentation says both use the same database. Unpaywall resolves open-access locations by Crossref DOI; it is not a general abstract/search service or a file extractor. Existing OpenAlex locations should be reused first. The earlier handoff also records retired Unpaywall search; this review's old API page rendered only a JavaScript shell, so the current recommendation relies on OpenAlex's accessible product documentation rather than a fresh retirement-endpoint test. [Current Unpaywall documentation](https://help.openalex.org/access/unpaywall/).
5. **OpenAlex itself already has a useful free tier.** Current pricing provides $1/day free account usage without a payment method, resetting at midnight UTC. Its MCP `get_work` returns the available full record, including abstract, and is documented as free. Search-list abstracts are intentionally shortened by the official MCP. This is distinct from any OpenAI model context/output limit. [Pricing](https://help.openalex.org/access/pricing/), [official MCP documentation/source](https://github.com/ourresearch/openalex-mcp-server).

## Capability and access comparison

“Free” below means a documented no-payment access option, not unlimited throughput or guaranteed full text. Corpus coverage, reuse terms and operational readiness differ.

| Source | Useful contribution | Free access and limits checked | Recommendation / current Scout state |
| --- | --- | --- | --- |
| **arXiv** | Direct preprint discovery, abstracts, versions and links, especially computing/math/physics. | Public API; at most one request every three seconds and one connection across controlled machines. Metadata includes abstracts; full-paper permissions are separate. | **First new adapter** for current AI topics. Probe passed; not integrated. |
| **OpenAIRE Graph** | Broad research graph, publication/data/software discovery, funding/project/organization relationships. | Free; currently 60 requests/hour anonymous or up to 7,200/hour authenticated. Attribution under CC-BY. Authentication is not payment; personal tokens expire after an hour and production services need the appropriate registered-service flow. | **Next broad alternative** after an access/schema/coverage trial. V3 probe passed; not integrated. [Terms](https://graph.openaire.eu/docs/apis/terms/), [authentication](https://graph.openaire.eu/docs/apis/authentication/). |
| **Europe PMC** | Biomedical/life-science papers and preprints, available abstracts, links, citations and subject terms. | Public REST; `core` rather than default `lite` supplies abstract metadata. No universal numeric request ceiling was established in this review; implement conservative pacing and honor server responses. | **First domain adapter** when evaluating biomedical questions. Probe passed; not integrated. |
| **PubMed / PMC** | Biomedical indexing, structured abstract sections and controlled query terms; eligible PMC content paths. | E-utilities: 3 requests/s without key, 10/s with key; batch where supported. PubMed abstracts and PMC full articles are separate capabilities. | Add to fill measured gaps after Europe PMC, avoiding redundant automatic querying. |
| **Crossref** | Broad publication metadata search plus DOI/publisher metadata and deposited abstracts when present. | Public REST metadata, polite client identification and server limits. Abstract deposition is incomplete. | Extend the **existing DOI-only adapter** with explicit metadata discovery; not a reliable universal abstract supplier. [REST docs](https://www.crossref.org/documentation/retrieve-metadata/rest-api/). |
| **DOAJ** | Open-access journal/article metadata, available abstracts and original article links across disciplines. | Public metadata endpoints/downloads; metadata under CC0. Validate endpoint/freshness/rate behavior before adoption; no live API probe passed or was claimed here. | Useful second-wave OA corpus adapter. [Metadata](https://doaj.org/docs/faq/), [terms](https://doaj.org/terms/). |
| **DataCite / Zenodo** | Research datasets, software and repository records, descriptions/abstracts, versions, licenses and files where available. | Public metadata discovery; Zenodo currently documents 30 search requests/minute, with guest global limits of 60/minute and 2,000/hour. | Add when research artifacts are part of the journey. DataCite exact DOI lookup exists; general discovery/Zenodo do not. [DataCite queries](https://support.datacite.org/docs/api-queries), [Zenodo developer docs](https://developers.zenodo.org/). |
| **Semantic Scholar** | Complementary relevance/citation graph and paper abstracts where supplied. | Free access with quotas. Anonymous traffic shares capacity and can be throttled; introductory keyed allowance is 1 request/s. | Retain as optional; obtain its own key and prove search. Existing Scout details work; anonymous search returned 429. [Access guidance](https://webflow.semanticscholar.org/product/api). |
| **CORE** | Repository aggregation, metadata and available machine-readable full text. | Free options exist, but its terms require contact for several product/search/discovery uses regardless of general free eligibility. Published basic rate is one batch or five single requests per ten seconds. | **Conditional later candidate**, not a guaranteed free dependency for Scout. Do not infer entitlement from the homepage's “free” wording. [API](https://core.ac.uk/services/api), [terms](https://core.ac.uk/terms). |
| **Unpaywall** | DOI → OA locations, versions/license information. | Free resolver surface with contact-email workflow; same underlying database as OpenAlex. | Later access-resolution compatibility route, **not an independent discovery/abstract corpus**. No integration added. |
| **OpenAlex snapshot** | Local copy of the broad metadata graph for repeated local queries. | Public full snapshot is free and currently quarterly; more frequent managed sync is a separate service. Local storage/indexing/compute still have costs. | Later scale option, not a quick extra API or an unlimited hosted replacement. [Snapshot/product overview](https://help.openalex.org/access/overview/). |

No reviewed option establishes a complete equivalent to OpenAlex's broad graph **and** its hosted native semantic-search capability. OpenAIRE is the broadest alternative in this shortlist; arXiv and Europe PMC provide stronger direct content in their domains. That combination is more useful than replacing one index indiscriminately.

## Live evidence from this review

[Machine-readable probe receipt](../../docs/validation/2026-11-09-free-source-probes.json): one unauthenticated request per candidate, two records requested, no pagination/retry and **zero OpenAI calls**. These were direct endpoint probes, not Scout integrations or a search-quality benchmark.

| Candidate | Outcome | Abstract/description evidence |
| --- | --- | --- |
| arXiv Atom query | HTTP 200 | Two abstracts: 1,378 and 1,206 characters. |
| Europe PMC `core` query | HTTP 200 | Two abstract fields: 3,899 and 1,416 characters, including provider markup. These examples did not assert open full-text availability. |
| OpenAIRE Graph V3 | HTTP 200 | Two publication records; no description text in these two examples. Broad graph access proved, abstract uplift not proved. |

No claims of all-provider availability, complete abstract coverage, native semantic parity or unrestricted redistribution follow from these probes.

## Recommended execution sequence

1. **Finish the existing abstract path first:** show snippets immediately, fetch available full same-provider details on explicit request, reuse saved results and expose missingness. New answer requests should use richer saved records within the model context envelope. This fix is implemented in the [system-design delta](../../system-design/richer-sources-and-abstracts.md); earlier answers retain original citations.
2. **Add arXiv as an isolated provider service.** Use official Atom API, exact versioned IDs, no-key reads, a shared single-connection three-second pacer, bounded results and cached reads. Add explicit AI/preprint scope rather than automatic fallback on OpenAlex 429. Trial primary-repository abstract coverage against the saved AI questions.
3. **Trial OpenAIRE V3 for broad complementary discovery.** Prove useful field/abstract coverage, ID mappings, attribution and token renewal before making it a regular route. Its anonymous 60/hour limit is too small to treat as unlimited backup capacity.
4. **Add Europe PMC for life-science/medical scope.** Request `core`, preserve structured abstracts and PMC/PMID/preprint IDs, and add PubMed separately only where measurements justify the overlap. No need to route every computing query here.
5. **Expand the existing Crossref search adapter**, then evaluate DOAJ. Add DataCite/Zenodo discovery when datasets/software are required. Defer CORE pending applicable access conditions and Unpaywall until OA-location acquisition is useful.

Each proposed provider remains a separate process with its own client, credentials, pacing, journal/cache, capabilities and failures. Prefer official APIs over community MCP wrappers whose maintenance/capability has not been verified. They can still be reached by the application's MCP/agent tools without a model in the retrieval path.

Where native vector retrieval is not documented, use lexical candidate collection plus local query/document embeddings to rerank a bounded same-provider pool. That does not discover records outside the pool. Keep filters, branch scope and score provenance visible; do not silently replace a failed provider or blend fields between indexes. An identifier-linked complementary abstract remains a separately attributed observation, with preprint/published-version relationships preserved.

Measure abstract availability, complete-versus-truncated coverage, useful additional records after identifier deduplication, correct version relationships, latency, request consumption and zero-model discovery against representative questions. Use endpoint pacing, cached details, bounded pagination, cooldown/Retry-After handling and explicit partial results. Free access still requires these controls.
