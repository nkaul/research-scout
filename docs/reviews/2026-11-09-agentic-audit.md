# Research Scout agentic implementation audit

**November 9, 2026 · independent subagent code/evidence review**

Research Scout implements a working local framework with two actual Deep Agents/LangGraph graphs, a real application MCP transport, four isolated provider processes, durable source observations and human review. Its model is still a scripted `BaseChatModel`. The code does not establish live LLM reasoning, autonomous research quality or fully proven live discovery.

This review read the current repository and dated receipts. It made no external requests, research calls, model calls, credential reads or runtime changes. The parent review owns current local port/health verification and the architecture diagrams. A provider service reporting `ready` in fixture mode proves the local service is available; it does not prove upstream API/MCP authentication or live quality.

The parent's [November 9 runtime receipt](2026-11-09-runtime-status.json) confirms HTTP 200 from the core and all four provider health endpoints in fixture mode, `live_model_configured=false`, and a successful application-MCP initialize/tools-list handshake exposing exactly the two expected tools. The frontend on port 3100 was not reachable. No application research tool or external provider was called in that check.

## The actual discovery workflow

1. The UI submits a question, one discovery provider and supported structured filters to the application API. The core saves the run, admits one active execution and binds its scope. The lexical and semantic queries are currently **the same question text**; there is no implemented LLM query-rewriting/planning step. See [core.py](../../src/research_scout/core.py), lines 126–155 and 345–358.
2. The coordinator graph's scripted model calls `delegate_discovery()` once. The specialist graph's scripted model calls its bound `search_papers()` once.
3. The specialist uses an actual MCP `ClientSession` over loopback Streamable HTTP to invoke the application's `search_papers(run_id)` tool. It does not call provider APIs directly. See [runtime.py](../../src/research_scout/agents/runtime.py), lines 197–225 and 327–354.
4. The application MCP returns to core run admission and routing. The core sends an HTTP search request to the single selected provider process. That service concurrently runs lexical and semantic branches and emits NDJSON branch/source events. See [core.py](../../src/research_scout/core.py), lines 318–367; [service.py](../../src/research_scout/providers/service.py), lines 210–298.
5. Each valid observation is normalized, attributed, filtered, deduplicated and committed by the application. The core computes equal-weight reciprocal-rank fusion (`k=60`) on eligible branch ranks. The stored event stream reaches the UI through SSE **before** the final graph summary is ready. The summary is not a gate for reading or shortlisting. See [core.py](../../src/research_scout/core.py), lines 425–461 and 531–542; [contracts.py](../../src/research_scout/contracts.py), lines 130–132; [api.py](../../src/research_scout/api.py), lines 82–116.
6. When the search returns, the specialist receives compact title/abstract previews plus complete source ID/version references. Output validation rejects foreign/invented IDs, unsupported field references and mutation-shaped output. The coordinator returns the validated envelope and a scripted scope/availability note. See [context.py](../../src/research_scout/agents/context.py), lines 116–238; [runtime.py](../../src/research_scout/agents/runtime.py), lines 282–325 and 368–395.
7. Human include/exclude/reason actions, explicit details, DOI registry checks and exports use application APIs. They are outside agent authority. The shortlist cap is three; exports preserve chosen source snapshots and saved revisions. See [api.py](../../src/research_scout/api.py), lines 118–138; [core.py](../../src/research_scout/core.py), lines 544–582 and 801 onward.

The default successful fixture run makes four scripted generations, one delegation and one application MCP search. The harness limits are six generations, 6,000 input/1,500 output **UTF-8 byte upper-bound units** per generation. These are not provider token measurements. The twelve-model-HTTP-attempt value is a future ceiling; actual model HTTP use/cost is fixed at zero because no live model adapter exists. See [harness.py](../../src/research_scout/agents/harness.py), lines 12–17 and 69–84.

## Important implementation nuances for the next increment

- **Provider live mode and model live mode are separate today.** `run_discovery(mode='live')` raises an explicit “Live LLM execution is disabled” error. However, `Core._execute_agent()` does **not pass a mode argument** to that function; it takes the default fixture model. Therefore launching the services with `SCOUT_MODE=live` can route the scripted coordinator/specialist to live provider adapters if access is configured. It does not enable a hosted LLM, and it is inaccurate to claim that every provider-live run must be rejected by the runtime guard. See runtime.py lines 398–421, core.py lines 181–195 and store.py line 182. An explicit provider/model mode split and a regression test would make future configuration less ambiguous.
- **Semantic Scholar local embeddings are conditional, bounded reranking.** The provider CLI supports `--encoder-factory module:function` in live mode, and the service accepts that encoder. No concrete encoder implementation is shipped/configured. The main `scripts/dev.py` launcher has no encoder option. The code validates model/revision/dimensions/query/document modes/cosine compatibility and ranks only the fetched lexical pool (maximum twenty), so it cannot recover corpus candidates absent from that pool. See [provider CLI](../../src/research_scout/providers/__main__.py), lines 16–33; adapters.py lines 42–89 and 333–421.
- **No live model, token-priced budget or live research evaluation exists yet.** The fixture model proves orchestration/structural constraints. It does not prove reasoning quality, relevance, entailment, prompt-injection resistance of a real LLM, or literature recall.
- **No production graph checkpointing or database has been adopted.** App JSON state and independent provider journals are implemented; durable autonomous graph continuation is not. Interrupted runs remain readable without automatic rerun.
- **Current local processing is metadata-focused.** Normalization strips supplied markup, reconstructs OpenAlex inverted-index abstracts, normalizes DOI/fields and records missing/truncated metadata. Context packing bounds previews while retaining identities. This is not a PDF/full-text parsing, citation-graph expansion, web crawling, video or vector-database pipeline. See [normalization.py](../../src/research_scout/providers/normalization.py), lines 12–22, 25–60 and 74–108.
