# Live provider execution audit

**November 9, 2026 · planning only · provider access and retrieval**

This audit inspected provider code, local configuration, the launcher and current official documentation. It made no authenticated provider requests, changed no application/configuration files and did not run live discovery. The [implementation review](../../system-design/implementation-review-2026-11-09.md) remains the baseline for measured behavior. Its October 26 public probes are dated evidence, not today's connection proof.

Four local provider HTTP services are not four hosted MCP servers. Crossref, DataCite and Semantic Scholar use REST in this implementation. Existing Crossref/DataCite capabilities are exact DOI operations, not general topic-search agents. All four can participate in a useful conversation in their actual roles; making them universally searchable is a separate capability extension.

## Official interface facts verified for this plan

- **OpenAlex:** the connector documents OAuth-capable Streamable HTTP clients, user-account sign-in and the hosted endpoint above. Keep its broader author-profile/write capabilities outside Scout's read allowlist. The public server source still defines `query`, keyword/semantic modes, `limit`, `rerank`, and imported `from_year`/`to_year`/`types`. Published source is a comparison reference; the hosted server's actual `tools/list` is the acceptance contract. [Connector](https://help.openalex.org/access/connector/), [official server](https://github.com/ourresearch/openalex-mcp-server/blob/main/src/server.ts), [filter definitions](https://github.com/ourresearch/openalex-mcp-server/blob/main/src/filters.ts).
- **Native semantics:** OpenAlex's November 3 documentation describes provider-owned query embedding, a 2,000-character bound, at most 50 results and one semantic request per second. Year/type are supported; other filters have specific restrictions. Scout's ten-per-branch/twenty-union limit remains tighter. No separate embedding API or local vector database is needed for this route. [Semantic search](https://help.openalex.org/api/semantic-search/).
- **Crossref:** public REST metadata requires no sign-up; its documented routes include both singleton metadata and registration-agency lookup. Contact identification is appropriate for the polite pool. Keep these as separate admitted requests. [Crossref REST reference](https://www.crossref.org/documentation/retrieve-metadata/rest-api/).
- **DataCite:** unauthenticated public retrieval returns Findable DOIs; a miss is not proof that no DOI exists. Singleton responses are JSON:API records. [Public API](https://support.datacite.org/docs/rest-api), [singleton retrieval](https://support.datacite.org/docs/api-get-doi).
- **Semantic Scholar:** official product/tutorial guidance recommends keys, documents an introductory individual-key rate of one request per second across endpoints and distinguishes that allocation from the shared anonymous pool. A relevance-search endpoint is not proof of a native text-to-vector search contract. The current local semantic route remains a rerank of at most twenty records fetched by the lexical request. [API overview](https://webflow.semanticscholar.org/product/api), [official tutorial](https://webflow.semanticscholar.org/product/api/tutorial). The JavaScript-only API reference did not expose its complete schema through the text browser; capture and validate actual responses during preflight.

## Environment contract to implement after plan review

There is no repository `.env` file. Existing `.env`, `.env.local` and `frontend/.env.local` names are ignored by Git. The root agent separately checked credential-variable presence in the shell, without reading their values, and found none. Neither another repo's environment nor a connector login should be assumed to supply this application's grant.

| Existing variable | Meaning and required correction |
| --- | --- |
| `SCOUT_MODE` | Legacy single fixture/live label. Split provider mode and model mode before claiming a live AI workflow. Preserve explicit fixture regression mode. |
| `SCOUT_STATE_DIR` | Local state root. Use a separate live acceptance state directory so fixture records cannot be mistaken for live findings. |
| `SCOUT_CORE_URL`, `SCOUT_API_URL` | Loopback core/client addresses; the latter also backs the Next.js rewrite. These are not hosted model/provider endpoints. |
| `SCOUT_OPENALEX_URL`, `SCOUT_CROSSREF_URL`, `SCOUT_DATACITE_URL`, `SCOUT_SEMANTIC_SCHOLAR_URL` | Internal core-to-provider URLs on ports 8111–8114. Keep loopback HTTP restrictions for this local operational milestone. |
| `SCOUT_OPENALEX_OAUTH_TOKEN` | Existing manual bearer-token bootstrap. A refreshable OAuth token store should replace a requirement to paste expiring tokens repeatedly. Never emit tokens in receipts or chat. |
| `SCOUT_SEMANTIC_SCHOLAR_API_KEY` | Existing `x-api-key` credential, used only by the Semantic Scholar process. |
| `SCOUT_CONTACT_EMAIL` | Existing Crossref User-Agent contact; this is identification, not authentication. |

Proposed additions must be implemented before appearing as working configuration. Suggested names are `SCOUT_OPENALEX_MCP_URL`, `SCOUT_CROSSREF_REST_BASE_URL`, `SCOUT_DATACITE_REST_BASE_URL` and `SCOUT_SEMANTIC_SCHOLAR_REST_BASE_URL`, defaulting to the official HTTPS endpoints above. Restrict outbound credentials to each trusted provider origin, reject credential-bearing URLs/redirects and keep overrides separate from internal service routing. Core settings intentionally reject remote service URLs today; do not remove that boundary simply to fill in hosted upstream addresses.

Add `SCOUT_MODEL_MODE` and independent `SCOUT_OPENALEX_MODE`, `SCOUT_CROSSREF_MODE`, `SCOUT_DATACITE_MODE`, `SCOUT_SEMANTIC_SCHOLAR_MODE`, keeping `SCOUT_MODE` as a documented legacy alias. Explicit CLI overrides the provider-specific setting, which overrides the legacy/default mode. Root's combined plan owns the final hosted-model profile fields. For optional S2 embeddings, add launcher wiring for the existing CLI `--encoder-factory`, a pinned model/revision and cache location. Do not describe an encoder-factory string alone as an installed encoder. Add an OpenAlex OAuth token-store path and callback/client settings only after testing the actual authorization-server metadata; do not invent issuer, scope, refresh or client-registration values. The chosen hosted LLM needs its own secret/model/endpoint/usage profile, separately from provider configuration.

Launcher corrections are necessary: `scripts/dev.py` loads root `.env` with `override=False`, but its CLI mode defaults to `fixture` and then overwrites `SCOUT_MODE`; all children receive the same complete environment. Define precedence as explicit CLI → existing shell → repository `.env` → documented default, report resolved nonsecret settings, and pass each child only its needed secrets. Standalone provider/core entry points currently do not themselves load the root `.env`; document and test the supported launcher entry path. Frontend code must receive no upstream keys or OAuth tokens.

## Dependency-ordered provider work packages

1. **Configuration and readiness:** implement the explicit mode/endpoint contract and isolated child environments; create the ignored `.env` from reviewed values without replacing existing secrets; validate malformed/missing config; expose process health, configured access and dated live proof as different states. Current `access_configured` checks token presence only for OpenAlex and returns true for other live providers; it is not a credential validity test.
2. **OpenAlex authorization and contract proof:** implement supported OAuth sign-in/refresh or explicitly time-bounded manual bootstrap, initialize and list tools, verify supported schemas, run one bounded keyword/semantic pair and one details call. Retain `rerank:false`, no OQL fan-out, no write tools and no silent REST substitution. A separately chosen REST profile could be implemented later if needed, with its own access/contract evidence.
3. **Registry proof in parallel:** enable live Crossref/DataCite services; use representative DOIs for each agency; verify unknown-agency resolution, known-agency independence and separate metadata conflicts. Retry policy stays provider-owned and bounded. No extra key provisioning is needed for the public reads.
4. **Semantic Scholar access and hybrid proof:** configure the key, pace all upstream operations at the admitted per-key rate, respect 429/cooldown, test search/details, then install/select a compatible local encoder and wire the launcher. A model/revision, query/document modes, dimensions and cosine validation must be recorded. Missing abstracts keep title-only scope explicit; reranking cannot find records absent from its lexical pool.
5. **Live product acceptance:** root's agent/chat work connects only enabled and proved capabilities. Each child discovery run keeps a fixed provider, branch scope, operation IDs and separate provenance. Results can arrive progressively before summary completion. Registry observations remain separate from discovery fields, and the model cannot manufacture unavailable provider results.

The earlier no-automatic-retry behavior is a useful first-live default. Introduce cooldown/pacing before adding retries; any retry must debit the same provider attempt grant and never be multiplied by a core/client retry loop. Preserve uncertain outcomes rather than automatically replaying an operation after a transport interruption.

## Acceptance evidence required per integration

Record a sanitized timestamp, provider/service mode, upstream origin, schema version/hash where available, bounded request arguments or hashes, normalized record IDs, filter outcomes, attempts, native/encoder provenance, observed/unknown usage and failure category. Keep credentials, authorization headers, refresh tokens and raw SDK exceptions out of logs/exports.

- **Application MCP:** actual initialize/tools-list/search exchange; foreign/unadmitted run rejected; reopening saved results invokes no upstream tools.
- **OpenAlex:** both native branches execute under the same supported constraints; valid results appear before delayed semantic completion; overlap deduplicates within provider; details stay with OpenAlex. Missing/expired grant, unexpected tool schema and unknown mode fail visibly. Provider-internal requests remain unknown unless actually observable.
- **Crossref:** agency and metadata attempts counted separately; crossref/not-found/unsupported/unresolved states differ; unavailable Crossref does not stop OpenAlex or known-DataCite retrieval.
- **DataCite:** Findable DOI normalizes title/year/type/publisher; miss stays a visibility/provider miss; Crossref failures do not trigger a blind DataCite metadata request.
- **Semantic Scholar:** keyed search/details success; shared one-per-second admission; 429 does not create a retry storm; real local embeddings pass finite-dimension/zero-vector/configuration checks; failed semantic execution retains lexical records and a partial outcome.
- **All providers:** cancellation, timeout, malformed/oversized responses, network interruption, independent process outage and saved reopen/export are exercised. Each integration has its own proof status; one successful provider does not mark the others operational.

The external dependencies still needed are the user's OpenAlex OAuth sign-in, a Semantic Scholar key for reliable keyed acceptance, the agreed hosted-model profile/secret, and an S2 encoder selection if full hybrid is required there. Public registry enablement and most contract/configuration work can proceed without waiting for those grants once the execution plan is accepted.
