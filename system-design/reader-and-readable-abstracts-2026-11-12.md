# Reader clarity, duplicate versions and readable abstracts

November 12, 2026. This frontend refinement keeps backend evidence, provider identities, queries, ranking and saved project observations unchanged.

The reader now presents a small title and publication first, followed by the abstract and then a deduplicated author list. Completed metadata/details timing moves to a small footer clock tooltip; active loading masks retain elapsed feedback. Metadata coverage is no longer a nested disclosure or an availability count. The Metadata tab uses one flat record table and concise messages for unavailable fields or supplied excerpts. Source flags are checked against actual values so a stale missing-field flag does not label a populated field unavailable. Notes use a shorter heading, one-line scope guidance and the existing run decision/note controls.

Search display groups repeated provider records and normalized DOI matches. It additionally collapses conservative exact citation matches: a substantive title of at least 50 characters plus matching authors, publication year, venue and resource type. Punctuation remains significant. This addresses the inspected identical journal/Zenodo title without claiming that its different DOIs are the same identifier. Short generic titles, different authors or different venues are kept apart. Each original DOI/provider record remains attributable in the provider-record view; access information stays with the representative DOI rather than crossing DOI boundaries.

Each provider record displays its newest known saved revision. Numeric versions are compared numerically; otherwise known update/observation/publication timestamps decide. Opaque hashes are never sorted as version numbers. If chronology is absent for repeated versions of the same record, saved arrival order is the fallback. Original snapshots are not deleted. A newer streamed record can refresh an open reader through saved reads; closing the reader prevents reopening, and explicit historical project pins retain their chosen version.

Abstracts default to **Key points** in the reader and compact bullet points on paper cards. This is a local extractive presentation, not model generation: sentence segmentation selects complete original sentences, prioritizes reported findings and explicit caveats, removes exact sentence repeats and keeps original order. The reader shows up to four points; cards show up to two. **Original abstract** provides the unchanged text, and the existing card expansion/explicit missing-content lookup remains available. No new provider/model call occurs just to switch presentation. Selection can omit methods or context, so the UI identifies the points as selected sentences and retains the full abstract for interpretation.

The [validation receipt](../docs/validation/2026-11-12-reader-abstracts-final.json) records version/hash/citation grouping, original-text fidelity, author placement, timing relocation, flat metadata/Notes, progressive revision updates, saved project authority, loading guards and responsive saved-live inspection. Actual source attribution remains separate from bibliographic display grouping; backend answer evidence is unchanged.
