# Stable Search previews and video content

**November 11, 2026 · implementation follow-up to reported UI flakiness.** Keep the existing design and agent/provider stack. Main Search must remain a stable workspace when inspecting a paper or video.

## Findings and correction

Opening a main result previously called the legacy provider-run navigation handler. It replaced the conversation result component with the single-source workbench, rewrote the URL and replaced the composer text with the originating provider query. Closing and returning remounted the results, losing local filtering/reading context. Independent inline description expansion also allowed several large cards to expand at once. Recent Searches primarily listed provider sub-runs, which could reopen another view without the main resource tabs. Reopening the current search could additionally set its loading flag without triggering a fresh read, leaving Search disabled.

Main-result inspection now reads the exact originating saved run into one focused native dialog. The Search component, Papers/Videos tabs, query draft, local result filter, source/date choices and URL stay mounted underneath; the background is inert while the dialog is open. Closing or pressing Escape restores focus to the invoking card. Main-card abstract/description actions use this same preview rather than expanding separate cards. A request sequence fence prevents a delayed source read from opening after New research or a navigation change. Recent Searches prefers complete saved conversations. Legacy provider-run URLs and explicit Exploration inspection remain supported.

A live saved-result check additionally reproduced an initialization race: server-rendered tabs accepted an interaction before the saved-search component initialized, then appeared to revert. Tab buttons now remain disabled until hydration/preferences are ready. Search results retain one component across conversation IDs, hide records from the prior ID while opening another, and preserve a tab choice made while data loads. A delayed saved-question read cannot overwrite a query draft the user has started typing. Browser acceptance deliberately pauses JavaScript hydration and saved-result delivery to exercise this boundary.

## Video preview and transcripts

YouTube result cards have a lazy thumbnail, an image-failure placeholder and the original YouTube link. Preview opens the same focused dialog. The YouTube player loads only after pressing the preview thumbnail; opening the dialog alone does not embed playback or fetch captions. The player uses the `youtube-nocookie.com` origin and retains an external link for playback restrictions.

**Load transcript** explicitly requests details from the selected saved YouTube record through the existing core → isolated provider service path. One operation reserves at most four local research attempts: one official `videos.list` metadata request and at most three public-caption HTTP requests. Each public request passes the provider journal admission callback. Public reads have finite per-request timeouts and a YouTube-only HTTPS origin allowlist. No account cookies, proxy rotation, CAPTCHA bypass or hosted model call is configured. The existing local allowance is not increased.

The official captions download API requires authorization and permission to edit the video; the user's Data API key cannot grant arbitrary caption downloads. [Google caption download reference](https://developers.google.com/youtube/data/reference/rest/v3/captions/download). Public-caption access instead uses pinned `youtube-transcript-api==1.2.5`, without an account. That library documents public access and blocking limitations. [Maintainer documentation](https://github.com/jdepoix/youtube-transcript-api).

Captured captions are distinct from the description and include language, generated/published labeling, timestamped segments, retrieval origin and observed time. Store at most 600 segments, 2,000 characters per segment and 60,000 characters overall; mark truncation. Unavailable, blocked and failed outcomes are explicit and retain the video/description. A saved detail outcome reopens without a new external request; there is no background retry. The provider detail cache retains success for 24 hours and unavailable/blocked/error outcomes for five minutes so a later new run can try again within its own allowance. An existing inspected run retains its saved outcome. Immutable source-version observations preserve existing accounting and citations. Transcript data is not silently injected into model prompts or old answers.

Search thumbnails supplied by the official API are retained in normalization and conversation previews. Older saved records can display a thumbnail from their validated YouTube identifier without another Data API query. [Search snippet reference](https://developers.google.com/youtube/data/reference/rest/v3/search).
