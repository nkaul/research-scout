# Loading feedback and faster saved reads

November 11, 2026. This refinement retains the selected Dub-inspired UI, provider isolation and explicit research actions.

Initial saved Papers/Videos display skeleton rows until hydration and saved-result loading finish. New searches retain the atom activity indicator and progressive skeletons while returned entities remain usable. Changing a paper/video selection immediately shows a right-reader skeleton; stale content/actions remain inert until the requested record is ready. Separate masks cover video thumbnails, the explicitly opened video player, captions and inline PDFs. Failed content reads retain their existing error/fallback behavior.

Saved reads now avoid unnecessary work. The recent-run sidebar requests `GET /api/research-runs?summary=true&limit=12`; the store projects seven header fields under its lock without copying full entities, events or model traces. The default full-list API remains compatible. Conversation history uses a direct six-field projection rather than hydrating every conversation and then discarding its contents. Parent history is shared with Search results, and startup promises are reused during React effect replay.

The workspace keeps at most eight run snapshots in memory. Completed snapshots expire after 15 seconds and active ones after one second. Concurrent reads for the same run join one request. Moving between records in a cached run preserves its SSE subscription. New SSE states seed the cache; missing progressively arriving identities force a saved-state refresh. Successful run mutations invalidate pending reads and seed the returned snapshot. Revision checks prevent older GET, mutation or SSE responses from replacing newer records, eligibility or decisions. This cache stores saved application state only and never starts provider/model work.

Preview, project saving, provider observations, inline documents, date controls, reader tabs, chat and workspace controls use clearer SVG icons. Shared tooltips appear on mouse hover and keyboard focus, connect through `aria-describedby`, dismiss with Escape, fit narrow viewports and remain visible above native dialogs. They clone the trigger instead of inserting toolbar wrappers, preserving action alignment.

The startup audit measured a 2,858,962-byte full run-list response for 65 saved runs even though the sidebar only needs 12 headers. After an idle service restart, the same saved data produced a 2,794-byte response for 12 headers: a 99.9% payload reduction. One local GET measured 413.03 ms for the old full response, 6.52 ms for summaries and 3.60 ms for conversation headers; these single observations are not a controlled timing benchmark. Request-count tests prove one startup history request and one saved snapshot GET for same-run A → B → A selection. These are payload/request measurements, not a benchmark of live provider latency.

Validation and limits are recorded in the [combined receipt](../docs/validation/2026-11-11-loading-tooltips-final.json). Backend tests cover summary compatibility, bounds and projection isolation; browser checks cover delayed loading, cache races, navigation, custom date refresh and tooltip behavior. Cached-live review performs saved reads only. External research response times and YouTube/PDF playback availability still depend on their providers.
